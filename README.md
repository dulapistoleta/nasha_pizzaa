# «Наша пицца» — лендинг-меню неаполитанской пиццерии (Астана)

Одностраничное веб-приложение (Single Page Menu) для крафтовой пиццерии
«Наша пицца»: рисованный фон в духе «Звёздной ночи» Ван Гога, каталог меню
с фильтрацией по категориям, pop-up окно блюда и оформление заказа в WhatsApp.

## Стек

| Слой | Технология |
| --- | --- |
| Фреймворк | Next.js 16 (App Router, Turbopack) + React 19 |
| Стили | Tailwind CSS v4 (CSS-first конфигурация через `@theme`) |
| Анимации | CSS-переходы и `@keyframes` (без JS-библиотек анимации) |
| Иконки | Lucide React |
| Шрифты | `next/font` — Playfair Display (заголовки), Manrope (текст), Caveat (маркерные надписи) |
| Изображения | `next/image` + `sharp` (генератор плейсхолдеров) |
| Защита | CSP и заголовки безопасности, rate limiting в `proxy.ts` |
| Проверка | `puppeteer-core`: скриншоты состояний и аудит производительности |

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000

npm run build        # продакшн-сборка
npm start            # запуск собранного приложения
npm run typecheck    # проверка типов
npm run lint         # ESLint
npm run images       # перегенерировать изображения блюд
npm run audit:perf   # аудит производительности (нужен запущенный сервер)
```

### Почему без Framer Motion

Анимации открытия модального окна, корзины, шторки на мобильных и появления
карточек сделаны на CSS. Библиотека анимации весила ~83 КБ gzip и попадала
в стартовый бандл; после перехода на CSS начальный JS уменьшился
с ~250 КБ до 177 КБ. Подробности — в [docs/AUDIT.md](docs/AUDIT.md).

## Изображения блюд

Каждая карточка ожидает файл по пути `/images/dishes/[dish-slug].webp`
(например, `/images/dishes/pepperoni.webp`). Сейчас там лежат
сгенерированные «живописные» плейсхолдеры в стиле настенной росписи.

**Чтобы поставить реальные 4K-фотографии** — просто положите файлы
с теми же именами в `public/images/dishes/`. Код менять не нужно:
`DishImage` сначала показывает skeleton-лоадер, а при ошибке загрузки
рисует векторный фолбэк.

Список slug'ов — ключи `id` в `lib/menu-data.ts`:

```
pepperoni, margherita, quattro-formaggi, pear-gorgonzola, meat,
stracciatella, fettuccine-chicken-mushroom, combo-4-pizza, chicken-pizza,
carbonara, english-breakfast, shakshuka, italian-breakfast, mushroom-soup,
lentil-soup, pumpkin-soup, caesar-chicken, greek-salad, fries, potato-wedges,
nuggets, cheese-sticks, mors-1l, kompot-1l, cola-1l
```

## Данные заведения

Все реальные данные собраны в `lib/restaurant.ts` — единый источник правды
для шапки, контактов, футера и WhatsApp-заказа:

- адрес: г. Астана, район Есиль, проспект Мәңгілік Ел, 52 блок В2 (ЖК «Promenade Expo»);
- часы: ежедневно 10:00–22:00 (статус «Открыто/Закрыто» считается по времени Астаны);
- телефоны: +7 (777) 947-52-52 (WhatsApp), +7 (707) 777-96-50;
- УТП: печь 457 °C, выпечка 90 секунд, тесто 72 часа ферментации,
  100% итальянская моцарелла, halal-начинки.

БЖУ и граммовки в `lib/menu-data.ts` — демонстрационные, уточняются у технолога.
Позиции с флагом `demo: true` добавлены, чтобы категории не выглядели пустыми.

## Заказ в WhatsApp

`lib/whatsapp.ts` формирует сообщение строго в формате заведения:

```
Здравствуйте! Хочу заказать в "Наша пицца":
1) Пепперони x1,
2) Морс 1л x1.
Сумма: 5 380 ₸.
Адрес доставки: ...
```

Адрес и комментарий гость вводит в корзине; текст можно посмотреть
до отправки в блоке «Посмотреть текст сообщения».

## Безопасность

Все заголовки собраны в `lib/security-headers.ts` и применяются и в
`next.config.ts`, и в `proxy.ts` (чтобы отказные ответы тоже уходили защищёнными).

| Мера | Реализация |
| --- | --- |
| CSP, HSTS, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP/CORP | `lib/security-headers.ts` |
| Ограничение частоты: 120 запросов/мин на страницы, 1500 на оптимизацию картинок, 30 на `/api/*` | `proxy.ts` |
| Блокировка сканеров (`.env`, `.git`, `wp-login`, `phpmyadmin`…) без рендера страницы | `proxy.ts` |
| Только `GET`/`HEAD` — остальное `405` | `proxy.ts` |
| Санитайзинг адреса, комментария и имени (длина, управляющие и невидимые символы, переводы строк) | `lib/sanitize.ts` |
| Экранирование JSON-LD от разрыва `</script>` | `app/page.tsx` |
| Валидация корзины из localStorage (id блюда, диапазон количества) | `lib/cart-store.tsx` |

Проверить вживую:

```bash
curl -sI http://localhost:3000/ | grep -i content-security   # заголовки
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/.env   # 404
for i in $(seq 1 130); do curl -s -o /dev/null http://localhost:3000/; done  # появится 429
```

**Важно про rate limiting.** Счётчики живут в памяти процесса — этого
достаточно для одного инстанса. При нескольких инстансах или serverless
замените хранилище на Redis: интерфейс `RateLimitStore` в `lib/rate-limit.ts`
для этого и выделен, там же есть пример. Подробнее о компромиссах —
в [docs/AUDIT.md](docs/AUDIT.md).

## Производительность

Замер: `npm run build && npm start`, затем `node scripts/perf-audit.mjs http://localhost:3000`
в другом терминале. Профиль — мобильный, CPU ×4, кэш отключён.

| Метрика | До | После |
| --- | --- | --- |
| Занятость главного потока при скролле | 22.3 % | **17.3 %** |
| Пересчётов вёрстки за скролл | 254 | **0** |
| Постоянных анимаций | 40 | **15** |
| Начальный JS (gzip) | ~250 КБ | **177 КБ** |
| Шрифты | 268 КБ | **190 КБ** |
| HTML | 631 КБ | **404 КБ** |
| CLS | 0.0005 | **0** |

Цифры — из первого прохода оптимизации. На Chrome 152 (Skia Graphite,
растеризация идёт в GPU-процессе) та же команда показывает ~27 % занятости
главного потока при скрипте 0.02 с, стилях 0.14 с и вёрстке 0.001 с: главный
поток не считает, а ждёт кадр от GPU. То есть страница упирается в
растеризацию тяжёлой графики, а не в JS — подробности в
[docs/AUDIT.md](docs/AUDIT.md), § 3.7.

Правила, которые поддерживают эти цифры:

- анимируются только `transform` и `opacity`;
- во время скролла не читается геометрия (`getBoundingClientRect`) — позиции кэшируются;
- `backdrop-filter` и `mix-blend-mode` на мобильных не используются;
- декоративные бесконечные анимации отключены на экранах до 768 px;
- у фонового слоя `contain: strict` и отдельный слой компоновщика;
- стартовый экран показывает только рекомендованные позиции, остальные
  категории подгружаются по клику — в разметке первого экрана нет 25 карточек;
- карточки каталога — под `memo`, фильтр применяется отложенно
  (`useDeferredValue`), ключ карточки — только `dish.id`: клик по категории
  остаётся отзывчивым, а DOM и `<img>` переиспользуются;
- выделение текста — мягкий полупрозрачный тон вместо сплошного `--color-sun`:
  на насыщённом жёлтом сглаженные края глифов читались как смена начертания
  и выделенный текст выглядел «жирным». Разбор обоих багов — в
  [docs/AUDIT.md](docs/AUDIT.md), § 3.7.

## Визуальная проверка

```bash
npm run dev
node scripts/visual-qa.mjs http://localhost:3000
node scripts/perf-audit.mjs http://localhost:3000
node scripts/screenshot.mjs http://localhost:3000
```

`visual-qa` открывает приложение в headless Chrome, кликает по карточкам,
открывает модальное окно и корзину, применяет фильтр категории и складывает
скриншоты в `.screens/`, попутно сообщая об ошибках консоли.
`perf-audit` снимает метрики производительности (см. выше).

Путь к Chrome можно переопределить переменной `CHROME_PATH`.

## Доступность и производительность

- семантическая разметка, `aria-label` на иконочных кнопках, `role="tablist"` в ленте категорий;
- модальное окно и корзина закрываются по `Escape`, блокируют прокрутку страницы,
  возвращают фокус и помечены `aria-modal`;
- поддержка `prefers-reduced-motion` — параллакс и анимации появления отключаются;
- изображения отдаются через `next/image` с адаптивным `sizes`;
- весь фон нарисован векторами (SVG) — суммарный вес 25 webp-плейсхолдеров ≈ 0,7 МБ.
